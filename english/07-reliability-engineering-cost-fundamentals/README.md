# Phase 7: Reliability Engineering & Cost Fundamentals

**Stage:** Technical Lead

## Why this phase exists here

Once you can build and secure a system, an architect has to answer 'how available does this need to be, and what does that cost?' This phase didn't exist in the original curriculum — non-functional requirements and cloud cost reasoning had no home.

## The question this phase should leave you able to answer

> Why does 99.9% availability cost so much more than 99%?

## Sections in this phase
- **[Non-functional requirements](01-non-functional-requirements/README.md)** — The vocabulary — SLA, SLO, SLI, RTO, RPO — that turns 'make it reliable' into a specific, testable target.
- **[Disaster recovery & high availability](02-disaster-recovery-high-availability/README.md)** — What you actually build to hit those targets: multi-region, failover, backup and restore.
- **[Cloud cost / FinOps](03-cloud-cost-finops/README.md)** — The economic constraint that shapes every one of those decisions in the real world, not just in a whiteboard exercise.
