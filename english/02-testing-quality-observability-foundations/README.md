# Phase 2: Testing, Quality & Observability Foundations

**Stage:** Developer

## Why this phase exists here

Placed immediately after Phase 1, deliberately before distributed systems, so testing and observability become reflexes before failures start multiplying across processes. You cannot reason sensibly about AI observability in Phase 19 if you've never reasoned about observability at all.

## The question this phase should leave you able to answer

> How would you know if this quietly broke, before a user has to tell you?

## Sections in this phase
- **[Testing strategy](01-testing-strategy/README.md)** — The trade-offs behind test-pyramid shape, chaos engineering, and load testing — not just 'write tests,' but which tests, how many, and why.
- **[Observability foundations](02-observability-foundations/README.md)** — Logs, metrics, and traces as the nervous system every later phase assumes already exists under the system it's describing.
- **[Incident & on-call basics](03-incident-on-call-basics/README.md)** — A first real taste of 'something broke in production.' Grounds every later reliability phase in an operational mindset instead of pure theory.
