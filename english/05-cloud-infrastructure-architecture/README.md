# Phase 5: Cloud & Infrastructure Architecture

**Stage:** Technical Lead

## Why this phase exists here

Once you know what you're building (Phases 1-4), you need to know where it runs. Compute, networking, containers, and Kubernetes are the substrate every later phase — including every AI phase — ultimately deploys onto.

## The question this phase should leave you able to answer

> Why containerize this instead of just running it on a VM?

## Sections in this phase
- **[Cloud fundamentals](01-cloud-fundamentals/README.md)** — The primitives (compute, storage, networking, IAM) every cloud provider is built from, regardless of vendor.
- **[Containers](02-containers/README.md)** — The packaging unit almost everything above this phase quietly assumes.
- **[Kubernetes](03-kubernetes/README.md)** — The dominant way containers are orchestrated once you're past 'it runs on my machine.'
- **[Platform engineering](04-platform-engineering/README.md)** — How teams industrialize deployment — GitOps, IaC — once manual deploys stop scaling.
