# Phase 1: Architect's Developer Foundation

**Stage:** Developer

## Why this phase exists here

Everything above this phase is built on top of clean code, honest API contracts, and application-level structure. Skip it and you end up choosing microservices or CQRS without knowing what problem they actually solve inside a single codebase — pattern-matching instead of reasoning.

## The question this phase should leave you able to answer

> Why did we need microservices when a modular monolith could work?

## Sections in this phase
- **[1. Programming mastery](01-1-programming-mastery/README.md)** — The craft-level vocabulary — clean code, patterns, concurrency, error handling — that every later design decision quietly assumes you already have.
- **[2. API engineering](02-2-api-engineering/README.md)** — The contract layer that every component in every later phase, from a REST endpoint to an MCP tool, ultimately communicates through.
- **[3. Application architecture](03-3-application-architecture/README.md)** — How to structure one deployable unit. Every larger pattern later in the curriculum — microservices, event-driven systems, multi-agent systems — is a scaled-up variation of the same ideas.
