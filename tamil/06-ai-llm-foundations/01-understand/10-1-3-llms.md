# LLMs

> **Learning Path:** AI / LLM Foundations
> **Section:** 10.1.3 — Understand

### 1. Problem

Rule-based system வைத்து நீங்கள் மனித language-ஐ handle பண்ண முயற்சி பண்ணினால் என்ன ஆகும்?

ஒரு customer support ticket வருகிறது: "என் order 3 நாளா deliver ஆகல, refund வேணும்". 
இன்னொரு ticket: "order delay ஆகுது, refund பண்ணுங்க".
Rule-ல pattern match பண்ணணும். Synonyms, grammar, spelling mistake, context எல்லாம் மாறும்.

அதனால் if-else rules explode ஆகும். Coverage குறைவு. New intent வந்தால் model மாற்றணும்.

Engineers-க்கு தேவைப்பட்டது: **unstructured text-ஐ flexible-ஆ handle பண்ணும் ஒரு general model, ஒரு முறை train பண்ணினால் பல task-க்கு reuse ஆகும்.**

அதுதான் LLM வந்த காரணம்.

### 2. Mental Model

LLM-ஐ "உண்மையை தெரிந்து கொண்டு பதில் சொல்லும் புத்திசாலி" என்று நினைக்காதீர்கள்.

அது **அடுத்த token-ஐ predict பண்ணும் probability engine**.

Training time-ல மில்லியன் டோக்கன் text-ஐ பார்த்து, "இந்த context-க்கு அடுத்து என்ன வர வாய்ப்பு அதிகம்?" என்று distribution கற்றுக் கொள்கிறது.

அதனால் அது உங்களுக்கு plausible sounding output தரும். அது fact என்று உறுதி இல்லை.

Mental model: **Giant autocomplete + pattern memory, not a database or logical reasoner.**

### 3. How It Works

Core idea simple.

**Pre-training:** ஏகப்பட்ட public text-ஐ வைத்து self-supervised next token prediction. Transformer architecture + attention mechanism உதவியுடன் long-range dependencies கற்றுக் கொள்கிறது.

**Tokenization:** Text-ஐ sub-word tokens-ஆக split பண்ணி embeddings-ஆக மாற்றுகிறது.

**Inference:** Prompt வந்ததும், model அதே distribution-ல token by token generate பண்ணும். Temperature, top-p போன்ற parameters output-ன் randomness-ஐ கட்டுப்படுத்தும்.

Fine-tuning அல்லது in-context learning மூலம் domain style-ஐ adjust பண்ணலாம். ஆனால் base ability எப்போதும் prediction தான்.

### 4. Architectural Reasoning

LLM useful ஆகும் போது?

* Natural language understanding, summarization, classification, code generation போன்ற open-ended tasks.
* Fixed rules-ல capture பண்ண முடியாத variance அதிகமாக இருக்கும்.
* Human-like response தேவை.

Alternative என்ன?
* Rule-based / Regex: Deterministic, cheap, ஆனால் brittle.
* Retrieval-only: Facts accurate, ஆனால் generation இல்லை.
* Smaller task-specific model: Cheaper, faster, ஆனால் generalization குறைவு.

Architect-ஆக நீங்கள் choose பண்ணுவது: **Control vs Flexibility trade-off.** LLM flexibility தரும், ஆனால் determinism குறைக்கும்.

### 5. Trade-offs

* **Hallucination vs Coverage:** Model confident-ஆக தவறான தகவல் சொல்லும். Fact-critical system-ல இது பெரிய risk.
* **Latency & Cost vs Quality:** Bigger model = better output ஆனால் latency அதிகம், inference cost அதிகம். Production-ல autoscaling & caching must.
* **Context window limit:** Model ஒரு முறை பார்க்கும் token எண்ணிக்கை limited. Long conversation அல்லது document-க்கு summarization / chunking தேவை.
* **Non-determinism:** Same prompt-க்கு ஒவ்வொரு முறையும் சற்று மாறும் output. Idempotency இல்லை. Testing & operability கடினம்.

Failure mode: Prompt injection, data leakage via prompt, sensitive data model-க்கு போகும்.

### 6. Practical Example

Enterprise support system.

User query -> Intent classifier small model -> If factual query, RAG pipeline: query vectorize -> vector database search -> relevant KB chunks retrieve -> LLM-க்கு context-ஆக கொடுத்து grounded answer generate.

இங்கே LLM-ஐ generator-ஆக use பண்ணினோம், retriever-ஐ fact source-ஆக use பண்ணினோம். Pure LLM alone என்றால் refund policy hallucination ஆகும்.

Cost control-க்கு cheap model for first pass, expensive model only for final generation.
