### Problem

உங்கள் product-ல LLM-ஐ integrate பண்ணினீங்க. Prototype-ல 100 users, GPT-4o மாதிரி ஒரு frontier model-ஐ எல்லா request-க்கும் use பண்ணீங்க. சரியா வேலை செய்தது.

Production-ல traffic வந்ததும், daily active users 10k ஆகி, average prompt 1500 tokens, response 600 tokens ஆகும் போது bill ஒரே வாரத்துல $3k cross ஆகுது. CFO கேட்கறார், "இதை ஏன் இப்படி விட்டீங்க?"

இதுதான் model selection-ல cost பிரச்சனை. Quality மட்டும் பார்த்தா போதாது. Cost per request, latency, throughput எல்லாம் scale-ஆகும்போது architectural decision ஆகுது.

### Mental Model

LLM cost என்பது மூன்று விஷயத்தின் product.

**Tokens in × price per token + Tokens out × price per token + operational overhead**

Output token cost பெரும்பாலும் input-ஐ விட 3-10x அதிகம். Context window நீள, retrieval results அதிகம் சேர்த்தா input tokens உடனே பெருகும்.

ஒரு model-ஐ தேர்வு பண்ணுவது என்பது ஒரு trade-off surface-ல point தேர்வு பண்ணுவது:

Quality / Accuracy ↔ Cost per token ↔ Latency ↔ Context length

ஒரே feature-க்கு ஒரே model வேண்டாம். Query complexity வேறுபடும்.

### Architectural Reasoning

Model selection-ஐ ஒரு routing problem ஆக பாருங்கள்.

**Constraint என்ன?**
- Budget cap per month
- P95 latency SLA, e.g., <800ms
- Quality bar, e.g., factual correctness for financial advice
- Throughput: peak RPS

**Options என்ன?**
1. **Single frontier model** - GPT-4o, Claude Opus. High quality, high cost, high latency.
2. **Smaller fast model** - GPT-4o mini, Llama 3.1 8B. Low cost, low latency, quality drop on complex reasoning.
3. **Tiered routing** - Router service queries-ஐ classify பண்ணி simple → small, complex → large.
4. **Caching & prompt optimization** - Same prompt repeat ஆனால் cache hit. RAG context-ஐ trim பண்ணு.

ஏன் architect இப்படி choose பண்ணுவார்?
Simple classification, sentiment, FAQ மாதிரி tasks-க்கு frontier model overkill. 8B class model 90% accuracy கொடுக்கும், cost 10x குறைவு.

Complex multi-step reasoning, code generation, sensitive financial summary மாதிரி tasks-க்கு மட்டும் expensive model use பண்ணலாம்.

### Trade-offs

**Cost vs Quality:** Small model-ல hallucinations அதிகம். Wrong routing என்றால் user experience degrade ஆகும். Router தவறாக classify பண்ணினால் critical query cheap model-க்கு போகும்.

**Latency vs Cost:** Small models typically lower latency. Frontier models-க்கு queue time வரும். Real-time chatbot-ல latency முக்கியம்.

**Operational complexity:** Tiered routing என்றால் monitoring, evaluation, fallback logic வேண்டும். Model A fail ஆனால் Model B-க்கு failover. இது extra service, extra cost.

**Context cost:** Long context window கொண்ட model விலை அதிகம். RAG-ல top-k retrieval அதிகம் எடுத்தா tokens waste. Context management தான் cost control-ல முக்கியம்.

Failure mode: Cost optimization-க்காக over-aggressive caching பண்ணினால் stale data தரும். Prompt compression மிகைப்படுத்தினால் important context இழக்கும்.

### Practical Example

E-commerce customer support RAG chatbot.

Daily 50k queries.

நீங்கள் observability போட்டு பார்த்தீங்க:
- 65% simple FAQ: "return policy என்ன?", "tracking எப்படி பார்ப்பது?"
- 25% product comparison, order status lookup
- 10% refund dispute, escalation, multi-step reasoning

Design:
Router service → query classifier → 
`simple` → Llama 3.1 8B via vLLM on own GPU, $0.15 per M tokens
`medium` → GPT-4o mini, $0
