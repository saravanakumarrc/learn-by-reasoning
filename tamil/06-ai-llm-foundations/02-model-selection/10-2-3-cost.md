# Cost

> **Learning Path:** AI / LLM Foundations
> **Section:** 10.2.3 — Model selection

### 1. Problem

நீங்கள் ஒரு RAG agent கட்டுகிறீர்கள். Prototype-ல் GPT-4o உபயோகித்தீர்கள். 100 users test பண்ணும்போது response quality super ஆக இருந்தது. Production-க்கு போனதும் 10k users, ஒவ்வொரு request-க்கும் 2-3 calls, ஒரு call-க்கு 2k tokens.

Bill வந்ததும் shock. ஒரு மாதத்தில் $40k.

இங்கே pain point என்ன? Quality வேண்டும், ஆனால் cost கட்டுக்குள் இருக்க வேண்டும். Model selection என்பது feature முடிவு அல்ல, இது cost, latency, quality மூன்றுக்கும் இடையே tradeoff ஆகும்.

ஒரு service architect ஆக நீங்கள் கேட்க வேண்டியது: "இந்த use case-க்கு உண்மையில் என்ன level of reasoning தேவை?"

### 2. Mental Model

Model selection = **Workload-க்கு ஏற்ற engine தேர்வு**.

Car analogy போல: City traffic-க்கு Ferrari வேண்டாம். Highway drag race-க்கு scooter வேண்டாம்.

LLM-கள் வெவ்வேறு price/performance points-ல் உள்ளன. அதே task-ஐ சிறிய model-ல் செய்ய முடியுமா, அல்லது அதற்கு large reasoning model தேவையா? அதுதான் கேள்வி.

### 3. How It Works

Cost ஒரு variable-ல் மட்டும் இல்லை. மூன்று விஷயங்கள் சேர்ந்து வருகின்றன:

**1. Per-token price:** Input token, output token, cache hit rate
**2. Latency & throughput:** Time to first token, tokens/sec, concurrency limit
**3. Quality for task:** Accuracy, hallucination, instruction following, context length handling

ஒரு request-ன் total cost = `tokens * price per token * number of calls`

RAG-ல் number of calls அதிகம்: retrieval + rerank + generation + tool call. ஒவ்வொரு call-மும் cost-ஐ கூட்டும்.

அதனால் model selection-ல் நாம் பார்ப்பது:
* Task complexity
* Latency budget
* Accuracy tolerance
* Volume

### 4. Architectural Reasoning

Model selection என்பது ஒரே model-ஐ எல்லாவற்றுக்கும் பயன்படுத்துவது அல்ல.

**Routing / Tiering** என்பது common pattern.

* Simple classification, summarization, entity extraction → small fast model. `embedding` + `small LLM`
* Complex reasoning, multi-step planning → larger model or reasoning model
* High volume user-facing chat → cheap model + caching
* Low volume critical decision → expensive model

Constraint பொறுத்து தேர்வு மாறும்:

* **Latency sensitive** → small model, distilled model, lower temperature
* **Cost sensitive** → smaller context window, aggressive prompt compression, cache
* **Quality sensitive** → larger context, reasoning model, higher temperature

Alternatives:
* Single premium model for all → simple, expensive
* Cascading: small model first, fallback to large if confidence low → cost save
* Model router based on query complexity → operational overhead

Architect ஏன் cascade choose பண்ணுவார்? 80% queries simple ஆக இருக்கும். அதை cheap model-ல் முடித்து, 20% hard queries-ஐ மட்டும் expensive model-க்கு அனுப்பினால் cost 60-70% குறையும்.

### 5. Trade-offs

**Quality vs Cost:** Larger model generally better, but diminishing returns. $0.02/input token vs $0.0005/input token. 40x வித்தியாசம்.

**Latency vs Cost:** Reasoning models think longer, output அதிகம் → cost + latency இரண்டும் அதிகம்.

**Context length vs Cost:** Long context = more input tokens = more cost. 128k context தேவைப்படாமல் 8k-க்குள் fit செய்ய முடியுமா என்று பார்க்க வேண்டும்.

**Operational complexity:** Multiple models, routing logic, monitoring, fallback = complexity அதிகம். Team size மற்றும் operability cost-ஐ கவனிக்க வேண்டும்.

Failure mode: Wrong model for task → hallucination அதிகம், user trust குறையும். அல்லது over-provisioning → burn cash.

### 6. Practical Example

Enterprise support bot.

Requirements: 50k queries/day, P95 latency < 2 sec, cost target <$1k/month.

Architecture decision:
* Tier 1: Query classification + intent extraction using small model `3B` class. 70% queries FAQ தீர்வு.
* Tier 2: RAG with `8B` class model, 4k context, cached embeddings. 25% queries.
* Tier 3: Escalation to `large reasoning model` for ambiguous/complex cases. 5% queries.

Caching: Frequent questions-ன் response-ஐ Redis-ல் cache. Embedding cache hits.

Prompt engineering: System prompt concise, no unnecessary examples. Input token குறைக்க.

Result: Average cost per query $0.004 → monthly ~$600. Single premium model use பண்ணியிருந்தால் $12k+.

### 7. Reasoning Challenge

உங்களிடம் ஒரு code review agent இருக்கு. ஒவ்வொரு PR-க்கும் 2000 lines code, ஒரு review. Team 100 engineers, நாளொன்றுக்கு ~300 PRs.

Option A: ஒரு பெரிய reasoning model, $0.03 per 1k tokens.
Option B: Small model for diff summarization + large model மட்டும் critical files-க்கு.

Latency budget 10 sec. Cost target முக்கியம்.

நீங்கள் எந்த architecture தேர்வு செய்வீர்கள்? Routing logic எப்படி வடிவமைப்பீர்கள்? Cost-ஐ குறைக்க மேலும் என்ன techniques உபயோகிப்பீர்கள்?

### 8. Key Takeaways

* Model selection என்பது quality மட்டும் அல்ல, cost-latency-quality trade-off ஆகும்.
* ஒரே model எல்லாவற்றுக்கும் அல்ல. Cascading / routing வழக்கமான architectural pattern.
* Token count, call frequency, cache hit rate ஆகியவை cost-ஐ தீர்மானிக்கின்றன.
* Workload-ஐ புரிந்து கொண்டு, task complexity-க்கு ஏற்ற engine தேர்வு செய்யுங்கள்.
