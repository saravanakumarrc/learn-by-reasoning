# OCR

> **Learning Path:** RAG Architecture
> **Section:** 12.1.4 — Learn

## 1. Problem

உங்களிடம் ஒரு RAG pipeline இருக்கு. LLM-க்கு context கொடுக்க documents தேவை. ஆனால் உங்கள் enterprise-ல் 80% information இன்னும் PDF, scanned invoice, ID card photo, handwritten notes, form scan மாதிரி unstructured image-ல தான் இருக்கு.

Text extraction இல்லாமல் RAG வேலை செய்யாது. Simple file upload பண்ணி text படிச்சா போதாது. OCR இல்லாமல் என்ன ஆகும்?

- Scanned contract-ல் உள்ள clause-ஐ search பண்ண முடியாது
- Invoice-ல் amount, vendor name extract பண்ண முடியாது
- Agent-க்கு answer கொடுக்க source document இல்லை

Problem clear: **Image / scanned document-ல் இருக்கும் text-ஐ machine-readable text-ஆக மாற்ற வேண்டும்.** அதுவும் layout, table, field context-ஓடு.

## 2. Mental Model

OCR = Optical Character Recognition. புகைப்படம் / scan-ல் உள்ள visual text-ஐ read பண்ணி digital text-ஆக மாற்றுவது.

ஆனால் architect-க்கு முக்கியம் இது ஒரு **pre-processing stage** மட்டுமே. Raw image → text + structure → embedding → vector database.

Mental model: OCR என்பது RAG pipeline-ல் ingestion layer-ன் ஒரு transformation step. இது accuracy, latency, cost மூன்றுக்கும் trade-off பண்ணும்.

## 3. How It Works

எளிமையாக:

1. **Pre-process**: Image enhance, skew correction, binarization. Quality கெட்ட scan-க்கு இது critical.
2. **Text detection**: Where is text? Layout analysis. Table detection, column detection.
3. **Recognition**: CNN + Transformer based models text-ஐ read பண்ணும். Modern OCR = Vision Encoder + Sequence Decoder.
4. **Post-process**: OCR output-ஐ clean பண்ணி, reading order restore பண்ணி, structure JSON / markdown-ஆக மாற்றுவது.

Tesseract போன்ற classic OCR-க்கு language model இல்லை. Modern OCR like EasyOCR, PaddleOCR, Azure Document Intelligence, Google Document AI இவை layout understanding + table extraction கொடுக்கும்.

RAG-க்கு முக்கியம்: plain text மட்டும் போதாது. **Where the text came from matters.** அதனால் OCR output-ஐ page number, bounding box, confidence score-ஓடு store பண்ணுவோம். Retrieval-ல் citation காட்ட உதவும்.

## 4. Architectural Reasoning

எப்போது OCR தேவை?

- Document ingestion pipeline-ல் source நிறைய scanned / image-based ஆக இருக்கும்போது
- Real-time capture வேண்டும்: mobile camera-ல் ID scan, receipt capture
- Historical archive digitization

Options:

**A. Client-side OCR**: Mobile app-ல் on-device model. Latency குறைவு, privacy நல்லது. ஆனால் model size, accuracy limit.

**B. Server-side API OCR**: Document Intelligence API, AWS Textract. Accuracy high, maintenance குறைவு. Cost per page, network latency உண்டு.

**C. Hybrid**: Fast pre-check client-ல், heavy extraction server-ல்.

Architect decision point: **Throughput vs Accuracy vs Cost.**

Low volume, high accuracy needed legal documents → managed API.

High volume, cost sensitive invoices → self-hosted model + GPU batch processing.

Real-time user-facing → async processing + webhook. User upload பண்ணிட்டு "processing" state காட்டுவது.

## 5. Trade-offs

**Accuracy vs Speed**: Better model slow. Production-ல் 95% accuracy வேண்டும் என்றால் preprocessing + post-validation தேவை.

**Layout preservation vs plain text**: Plain text cheap. Table, form field extraction வேண்டுமென்றால் structured output வேண்டும். RAG retrieval quality improve ஆகும், ஆனால் pipeline complex ஆகும்.

**Cost**: API per page charge. 1M pages/month → serious cost. Self-hosted fixed infra cost but ops overhead.

**Failure modes**: Handwritten text, low resolution scan, multi-language mixed, rotated pages. இவை OCR-ஐ fail பண்ணும். Confidence threshold வைத்து human-in-the-loop review queue-க்கு அனுப்ப வேண்டும்.

**Privacy**: Documents may contain PII / financial data. OCR service third-party-க்கு அனுப்புவது data residency problem. On-prem model தேர்வு security constraint.

## 6. Practical Example

Enterprise finance RAG system. Vendor invoices PDF & photo வருகிறது.

Architecture:
Upload → S3 → Event → Lambda trigger → OCR service.
OCR output: JSON with fields: vendor_name, invoice_date, amount, line items table, raw text + bounding boxes.
Post-process: Normalize amount, validate with regex, confidence <0.8 என்றால் human review queue-க்கு.
Text + metadata → chunking → embedding → vector database with metadata filter by vendor, date.

LLM query: "Last month Acme vendor-க்கு எவ்வளவு pay பண்ணோம்?" → vector search + metadata filter → citation with original page image link.

இங்கே OCR தான் bottleneck. Wrong amount extract ஆனால் RAG answer wrong.

## 7. Reasoning Challenge

உங்களிடம் bank statement images வருகிறது. 10,000 images per day. Handwritten notes சில இடத்தில் இருக்கு. OCR API cost $0.015 per page. Self-hosted model infra cost $2000/month fixed.

Latency requirement: 5 minutes within upload.

இங்கே என்ன தேர்வு செய்வீர்கள்? Hybrid workflow எப்படி design பண்ணுவீர்கள்? Handwritten portion-க்கு என்ன பண்ணுவீர்கள்?

## 8. Key Takeaways

- OCR என்பது RAG ingestion-ன் prerequisite, not retrieval magic.
- Accuracy, layout understanding, cost மூன்றும் architectural decision-ஐ drive பண்ணும்.
- Confidence score-ஐ store பண்ணி human review loop வைத்தால் reliability கிடைக்கும்.
- Every OCR solution creates new trade-off: cost vs accuracy vs ops complexity.
