# BM25

> **Learning Path:** RAG Architecture
> **Section:** 12.1.12 — Learn

## 1. Problem

உங்கள் RAG system-ல LLM க்கு context கொடுக்கணும். User question வந்ததும் vector database-ல similarity search பண்ணி top-k chunks எடுக்கிறீர்கள்.

ஒரு முக்கியமான பிரச்சனை வரும்: **semantic similarity இருந்தாலும் exact keyword match இல்லாத போது**.

Example: User கேட்கிறார் "order return policy for damaged items". உங்கள் chunk-ல "damaged goods return window is 7 days" இருக்கு. Embedding similarity நல்லா இருக்கலாம். ஆனால் "refund", "return", "policy" போன்ற exact terms இல்லாமல் வேறு paraphrase இருந்தால் vector search miss ஆகும்.

மறுபுறம், pure keyword search பண்ணினால் "return policy" exact phrase இருக்கும் chunk-ஐ கண்டிப்பா கண்டுபிடிக்கும். ஆனால் synonym, typo, language variation க்கு கண்ணை மூடிக்கொள்ளும்.

**Problem ஆகிறது:** Vector search alone lexical signal-ஐ miss பண்ணும். Keyword search alone semantic signal-ஐ miss பண்ணும்.

இதை தீர்க்க தான் BM25 வருகிறது.

## 2. Mental Model

BM25 ஒரு **lexical ranking function**. அதாவது query terms எத்தனை முறை, எந்த density-ல document-ல் வருகிறது என்பதை statistical weight-உடன் score பண்ணும்.

Mental model: 
`Score = term frequency * inverse document frequency`

ஒரு term அந்த corpus-ல் அரிதாக இருந்தால் அது valuable. அதே term ஒரு document-ல் அதிகமாக repeat ஆனால் அதிக valuable. ஆனால் saturation இருக்கும் — 10 முறை வந்தாலும் 11 முறை வந்ததை விட அதிக difference இல்லை.

BM25 இது ஒரு classic information retrieval formula. Embedding இல்லாத காலத்திலேயே search engines உபயோகித்தது.

## 3. How It Works

BM25 query terms ஐ tokenize பண்ணி ஒவ்வொரு document-க்கும் score கணக்கிடும்.

Key ideas:

* **TF:** term frequency in document. normalization உண்டு.
* **IDF:** term எவ்வளவு rare என்பது corpus அடிப்படையில்.
* **Document length normalization:** நீளமான document தானாகவே அதிக term count பெறும். அதை normalize பண்ணுகிறது.

Result: ஒரு ranked list of documents purely based on lexical match, no embeddings, no model.

Fast, deterministic, explainable.

## 4. Architectural Reasoning

RAG architecture-ல BM25 எங்கே வருகிறது?

**Hybrid Retrieval** pattern:

1. Query வந்தது
2. Vector search → semantic candidates
3. BM25 search → lexical candidates
4. Merge / rerank → final top-k

எப்போது useful?

* Query-ல proper nouns, product codes, dates, exact phrases இருக்கும் போது. "Invoice #INV-2024-8841" போன்றது embedding-ல blur ஆகும். BM25 exact match கொடுக்கும்.
* Short queries. "Python list comprehension" போன்ற query-க்கு vector alone noise ஆகும்.
* Corpus-ல domain-specific terminology இருக்கும் போது. Synonym expansion இல்லாமல் term exactness முக்கியம்.

Alternative என்ன? Pure vector. Pure keyword. Sparse retrieval BM25 மட்டும். Cross-encoder reranker.

Architect choose BM25 because:
* Cheap and fast. No GPU needed.
* Explainable. ஏன் இந்த chunk select ஆனது என்று term match காட்ட முடியும்.
* Complements vector. Vector catches paraphrase, BM25 catches exactness.

## 5. Trade-offs

**Pros:**
* Lexical precision உண்டு. Exact term match உறுதி.
* Zero training cost. Corpus statistics மட்டும் போதும்.
* Latency குறைவு. Inverted index-ல fast.

**Cons:**
* Semantic understanding இல்லை. "car" vs "automobile" different.
* Synonym, typo, morphological variation-க்கு கண் மூடும்.
* Language dependent. Stemming/tokenizer தேவை.
* Query expansion இல்லாமல் recall குறையும்.

Failure mode: BM25 மட்டும் பயன்படுத்தினால், rephrased questions miss ஆகும். Vector மட்டும் பயன்படுத்தினால், rare exact entities miss ஆகும். அதனால் hybrid தேவை.

## 6. Practical Example

Enterprise support RAG.

Corpus: 200k support tickets + KB articles.

User query: "How to reset MFA after phone loss?"

Vector search gives articles about "multi-factor authentication recovery", "lost device". Good.

BM25 search gives article with exact phrase "reset MFA after phone loss" and ticket containing "phone lost mfa reset steps". 

Hybrid merge-ல top 10-ல இரண்டும் வரும். Reranker இறுதியாக best 5 choose பண்ணும்.

Result: Recall increase 15-25% typical.

Implementation: Elasticsearch/OpenSearch BM25 default scoring. அல்லது Lucene based. LangChain `BM25Retriever`. Faiss + BM25 hybrid.

## 7. Reasoning Challenge

உங்களிடம் legal contract QA system உள்ளது. Queries-ல clause numbers, section names, exact legal phrases அதிகம். Corpus 50k documents.

நீங்கள் vector search மட்டும் வைத்திருக்கிறீர்கள். Users complain "Section 12.4 indemnification" என்று கேட்டாலும் relevant clause திரும்பி வருவதில்லை.

இங்கே BM25-ஐ எப்படி integrate செய்வீர்கள்? Weight எப்படி balance செய்வீர்கள்? Recency bias தேவையா?

## 8. Key Takeaways

* BM25 என்பது lexical sparse retrieval. Vector dense retrieval-க்கு complement.
* Exact terms, entities, codes க்கு BM25 வலிமையானது. Semantic paraphrase-க்கு vector.
* Hybrid retrieval = vector + BM25 + rerank. இதுவே production RAG-ல standard pattern.
* BM25 cheap, deterministic, explainable. Trade-off semantic flexibility.
* Architect decision: Precision vs recall, latency vs quality, cost.

இது ஏன் தேவைன்னு புரிஞ்சுது. எப்போ use பண்ணணும்னு தெரியும்.
