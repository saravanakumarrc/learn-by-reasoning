# Phase 3: Distributed Systems

**Stage:** Senior Developer

## இந்த phase ஏன் இங்க இருக்கு

System ஒரு process boundary-ஐ cross பண்ணின மாத்திரம், failure modes முழுசா மாறிடும். இது இந்த curriculum முழுசுலயும் இருக்கிற மிகப்பெரிய mental-model shift — bad architecture பெரும்பாலும் வர்றது distributed call-ஐ local function call மாதிரி treat பண்றதால தான்.

## இந்த phase முடிச்ச பிறகு answer பண்ண முடிற question

> Phase 1-ல பண்ணி மாதிரி, ஏன் இங்க வெறும் try/catch add பண்ணா போதாது?

## இந்த phase-ல இருக்கிற sections
- **[Core concepts](01-core-concepts/README.md)** — Distributed systems-ஓட physics — CAP, consensus, ordering, partial failure. இவை design பண்ணும்போது கணக்கில எடுத்துக்கணும் constraints, apply பண்றதுக்கான technique இல்ல.
- **[Messaging](02-messaging/README.md)** — Decoupled components practical-ஆ எப்படி communicate பண்ணுது — event-driven architecture-க்கும், later agent-to-agent communication-க்கும் இதுதான் backbone.
