# Phase 2: Testing, Quality & Observability Foundations

**Stage:** Developer

## இந்த phase ஏன் இங்க இருக்கு

Phase 1 முடிச்ச உடனே, distributed systems ஆரம்பிக்குற முன்னாடியே intentional-ஆ இந்த phase வைச்சிருக்கோம் — process-கள் அதிகமாகி failure-கள் multiply ஆகுறதுக்கு முன்னாடியே testing, observability-ஐ ஒரு reflex-ஆ மாத்திடணும். Ordinary software-க்கே observability பத்தி reason பண்ண தெரியாம, Phase 19-ல AI observability பத்தி reason பண்ண முடியாது.

## இந்த phase முடிச்ச பிறகு answer பண்ண முடிற question

> User கிட்ட சொல்றதுக்கு முன்னாடியே, silent-ஆ break ஆனது எப்படி தெரிஞ்சுக்குவீங்க?

## இந்த phase-ல இருக்கிற sections
- **[Testing strategy](01-testing-strategy/README.md)** — Test pyramid shape, chaos engineering, load testing பின்னாடி இருக்கிற trade-off-கள் — 'test எழுது'ன்னு மட்டும் இல்ல, எந்த test, எத்தனை, ஏன்னு.
- **[Observability foundations](02-observability-foundations/README.md)** — Logs, metrics, traces — இது later phase-ல இருக்கிற ஒவ்வொரு system-க்கும் கீழ இருக்கும்னு assume பண்ற nervous system.
- **[Incident & on-call basics](03-incident-on-call-basics/README.md)** — 'Production-ல ஏதோ break ஆயிடுச்சு'ன்ற முதல் real experience. இது later reliability phase-கள் எல்லாத்தையும் ஒரு operational mindset-ல ground பண்ணும், pure theory-ல இல்ல.
