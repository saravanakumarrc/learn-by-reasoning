# TLS

> **Learning Path:** Security Architecture
> **Section:** 6.1.9 — Application security

## Problem

உங்கள் API public internet-ல run ஆகுது. Client browser-ல இருந்து request வருது. அது plaintext HTTP-ல போனா என்ன ஆகும்?

Network-ல யார் வேணும்னாலும் tcpdump / Wireshark போட்டு packet-ஐ படிக்கலாம். Username, password, token, PII எல்லாம் தெரிஞ்சுடும். இடையில் ஒருத்தர் நின்னு response-ஐ மாற்றி அனுப்பலாம். Client-க்கு இது உண்மையான உங்கள் server தானா என்று தெரியாது. Server-க்கும் client உண்மையானவன் தானா என்று தெரியாது.

இந்த மூன்று வலி இருக்கு:
**Eavesdropping** - யாரோ கேட்டுக்கொண்டிருக்கிறார்கள்
**Tampering** - யாரோ மாற்றி அனுப்புகிறார்கள்
**Impersonation** - fake server/client

இதை தடுக்க ஒரு standard வேண்டும். அதுதான் TLS.

## Mental Model

TLS-ஐ ஒரு sealed envelope-ஆக பாருங்கள்.

* Lock: Data-ஐ encrypt பண்ணி, மூன்றாம் நபருக்கு படிக்க முடியாமல் செய்வது.
* Seal: Data மாற்றப்படவில்லை என்பதை verify செய்வது.
* ID card: Server யார் என்பதை certificate-ஆல் நிரூபிப்பது.

Encryption மட்டும் போதாது. Identity இல்லாமல் encrypted connection-க்கும் மதிப்பு இல்லை.

## How It Works

TLS-ன் core idea simple: **asymmetric crypto for key exchange, symmetric crypto for data**.

Handshake மூலம் இரண்டு பக்கமும் ஒரு temporary session key உருவாக்கிக்கொள்ளும்.

```
sequenceDiagram
participant Client
participant Server
Client->>Server: ClientHello
Server-->>Client: ServerHello + Certificate
Client->>Server: KeyExchange + Finished
Server-->>Client: Finished
Note over Client,Server: Encrypted application data with AES-GCM
```

ClientHello → ServerHello + Certificate → Client verifies certificate via trusted CA chain. Key exchange ECDHE மூலம் செய்யப்படும். இரண்டு பக்கமும் same session key-ஐ derive செய்து, அதன் பின் application data symmetric encryption-ல் போகும்.

TLS 1.3 இதை 2 round trip-க்குள் முடிக்கிறது. Forward secrecy கிடைக்கிறது. Server-ன் private key கசிந்தாலும் பழைய session-ஐ decrypt முடியாது.

Mutual TLS என்றால் client-ம் ஒரு certificate கொடுத்து தன்னை authenticate செய்கிறது.

## Architectural Reasoning

TLS பயன்படுத்த வேண்டியது எங்கே?

* Public internet-க்கு போகும் எல்லா traffic-க்கும். Browser → API, mobile app → backend.
* Service-to-service communication-ல், especially multi-tenant VPC-ல். Network isolated என்று நினைத்தாலும் insider threat, misconfiguration இருக்கும்.

Architectural choice: Termination எங்கே?

* Edge termination: API Gateway / Load Balancer-ல் TLS terminate செய்து, அதற்குள் plaintext. Simple, performance better. ஆனால் internal network trust பண்ணுகிறீர்கள்.
* End-to-end TLS: Edge-ல் terminate செய்து, service mesh / sidecar மூலம் service-to-service கூட TLS. Operability கஷ்டம் ஆனால் defense in depth.

mTLS என்பது service identity-ஐ certificate-ஆல் கட்டுப்படுத்துவது. IP based allow list போதாது.

## Trade-offs

* **Performance vs Security**: Handshake CPU cost, latency. TLS 1.3, session resumption, TLS offload hardware/accelerator மூலம் குறைக்கல
