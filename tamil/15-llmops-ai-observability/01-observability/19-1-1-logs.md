# Logs

> **Learning Path:** LLMOps / AI Observability
> **Section:** 19.1.1 — Observability

## 1. Problem

உங்க system-ல ஒரு request fail ஆகுது. Customer complain பண்ணார். நீங்க என்ன பண்ணுவீங்க?

Logs இல்லாமல் நீங்க blind-ஆ இருப்பீங்க. Metrics சொல்லும் "error rate 2%". Tracing சொல்லும் "request 3 seconds ஆச்சு". ஆனா **ஏன்** fail ஆச்சு? எந்த service-ல, எந்த input-ல, எந்த code path-ல? 

Production-ல reproduce பண்ண முடியாத bug வரும். On-call engineer 2 AM-ல பார்க்கணும். அப்போ ஒரே விஷயம் உதவும்: **structured, searchable logs**.

Logs இல்லாமல் problem என்ன?
- Failure root cause கண்டுபிடிக்க 1-2 மணி நேரம் waste
- Post-mortem-ல கதை சொல்ல முடியாது
- Compliance audit-க்கு evidence இல்லை
- AI system-ல LLM call எதுக்கு fail ஆச்சு, prompt என்ன, latency எவ்வளவு — தெரியாது

## 2. Mental Model

Log என்பது system-ன் **black box recorder**. ஒவ்வொரு important event-உம் timestamp-உடன் write ஆகும்.

Observability triangle-ல logs என்பது **what happened** part. Metrics = what is happening now. Tracing = how request flows.

LLMOps / AI Observability-ல logs இன்னும் critical. ஏன்னா LLM call nondeterministic. Same prompt-க்கு different output. Cost, latency, token usage, guardrail trigger — இதையெல்லாம் log பண்ணாமல் optimize பண்ண முடியாது.

## 3. How It Works

ஒரு service ஒரு event-ஐ generate பண்ணும் போது:
`[timestamp] [level] [service] [request_id] message + context`

Structured logging-ல message JSON ஆக இருக்கும்.

```
{
  "timestamp": "2026-01-13T10:12:03Z",
  "level": "error",
  "service": "rag-retriever",
  "request_id": "abc123",
  "user_id": "u_42",
  "event": "vector_search_failed",
  "latency_ms": 3421,
  "error": "timeout"
}
```

இதை log shipper சேகரித்து centralized log store-க்கு அனுப்பும். Elasticsearch, Loki, CloudWatch Logs, OpenSearch போன்றவை.

Search & correlate பண்ண request_id-ஆல் எல்லா services-ன் logs-ஐ join பண்ணலாம்.

## 4. Architectural Reasoning

**When logs become useful?**
- Debugging production incidents
- Audit trail & compliance
- Understanding user behavior & business events
- AI system observability: prompt, completion, tool call, token usage, cost

**What constraint it addresses?**
Debuggability under uncertainty. System complex ஆகும்போது mental model போதாது.

**Alternatives?**
- Only metrics: சொல்லும் that error happened, why என்று சொல்லாது
- Only tracing: request flow தெரியும், ஆனா business logic details தெரியாது
- Console print in dev: production-ல scale ஆகாது, lose ஆகும்

**Architect choose ஏன்?**
Logs cheap to generate, high cardinality. என்ன வேண்டும் என்பதை நீங்களே decide பண்ணலாம். But you pay storage & ingestion cost.

## 5. Trade-offs

**Volume vs Value.** ஒவ்வொரு line-உம் log பண்ணினால் cost explode ஆகும். Too much noise = signal மறைந்து விடும். Important events மட்டும் log பண்ணணும்.

**Structured vs Unstructured.** Unstructured string easy to write, hard to query. Structured JSON queryable, but schema evolve ஆகணும். Engineer-க்கு overhead.

**Log level discipline.** DEBUG, INFO, WARN, ERROR. Production-ல DEBUG on ஆனால் performance hit & cost. Wrong level use பண்ணினால் critical event miss ஆகும்.

**PII & Security.** Logs-ல user data, prompt, API key வந்துவிடும். Mask பண்ணணும், retention policy வேணும். GDPR audit-ல பிரச்சனை.

**Failure mode:** Log pipeline down ஆனால் logs lost. Async shipping-ல backpressure வரும். Disk full ஆகி service crash ஆகும்.

## 6. Practical Example

Enterprise RAG service.

User query வந்தது. Retrieval step fail ஆனது. Tracing சொல்லும் latency 4s. Metrics சொல்லும் error rate spike.

Log:
```
{
 "request_id": "req_9k2",
 "event": "llm_call",
 "model": "gpt-4o-mini",
 "prompt_tokens": 812,
 "completion_tokens": 124,
 "latency_ms": 2100,
 "cost_usd": 0.0031,
 "guardrail": "pii_detected",
 "user_query_hash": "abc"
}
```

இதை பார்த்து architect புரிஞ்சுக்கிறார்: guardrail trigger ஆனதால் response blocked. Cost per request தெரியும். Same user repeated query பண்ணுகிறாரா என்பதும் தெரியும்.

இல்லாமல் நீங்க blind.

## 7. Reasoning Challenge

உங்க AI agent 1000 requests/min handle பண்ணுது. ஒவ்வொரு request-க்கும் full prompt & completion log பண்ணினால் storage 500GB/day ஆகும். Compliance 30 days retention கேக்குது. Cost குறைக்கணும்.

என்ன log பண்ணுவீங்க, என்ன skip பண்ணுவீங்க? Sampling எப்போ use பண்ணலாம்? PII எப்படி handle பண்ணுவீங்க?

## 8. Key Takeaways

- Logs = system-ன் memory. Metrics & tracing-உடன் சேர்ந்து observability complete ஆகும்
- Structured, correlated logs with request_id தான் production debugging-க்கு வேலை செய்யும்
- Log என்பது design decision: என்ன log பண்ணுறீங்க, எந்த level, எவ்வளவு நாள் keep பண்ணுறீங்க — இது cost, security, debuggability trade-off
- LLMOps-ல logs இல்லாமல் prompt drift, cost anomaly, guardrail failure புரிஞ்சுக்க முடியாது
